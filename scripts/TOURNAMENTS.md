# Регистрация турнира

В `scripts/tournaments.json` хранится JSON-массив дополнительных турниров. Для каждого укажи `key` (уникальное латинское имя для ссылки), `name` (отображаемое название), числовые `league_id` из OpenDota и `stage_id` из Cybersport. Поле `bracket_ids` — необязательный массив числовых ID сеток Cybersport. Заполни его, если в одном этапе есть квалификация и основной турнир. Без фильтра попадут все сетки этого этапа. PARI Universe и оба этапа 1win уже подключены.

После изменения файла в ветке `main` процесс Deploy static dashboard проверяет подтверждённые пары, время, формат серии и сыгранные карты. Тот же процесс запускается по расписанию, в том числе при закрытом браузере. Для немедленной повторной проверки доступен ручной запуск этого процесса в GitHub Actions.

Сетка берётся из зарегистрированного этапа Cybersport. Для результата сверяются матчи лиги OpenDota, команды, время, порядок карт и счёт серии. Когда счёт лиги недоступен, проверяется отдельная карточка игры и её статистика. Карта с противоречивыми источниками остаётся в ожидании подтверждения. Уже подтверждённые результаты сохраняются при сбоях источников. Сторонние названия и коды турниров сами по себе не связывают карту с прогнозом.

Для исходных PRE и POST турнир также должен обслуживаться моделью трекера. К сбору публичного расписания и результатов это требование не относится.

BLAST Slam IX (`blast-slam-ix`) включает группы, посев, последний шанс и плей-офф. У гранд-финала `10100697` официальный формат BO5, поэтому он задан в `best_of_overrides` вместо BO3 из предварительного расписания Cybersport. Исходный реестр 58 сыгранных карт независимо сверён с BLAST и точными Steam ID. Проверка `node scripts/test_blast_registry.cjs` сохраняет эту точку отсчёта при добавлении карт плей-офф.

Группы нового турнира подключаются вместе с расписанием. Если у пары есть связанная группа (`groupTable`) в Cybersport, реестр сохраняет её идентификатор и название. Сайт показывает общие таблицы групп с момента публикации подтверждённых пар. Списки команд и результаты пополняются по мере проверки источника. Отдельная правка интерфейса для нового турнира не требуется.

## История цен Polymarket

`python3 scripts/refresh_polymarket_prices.py --tournament pari-universe` обновляет справочные цены в `src/polymarket-api-prices.json`. Скрипт использует `curl`, реестр сыгранных карт, поиск событий Gamma и историю цен токенов CLOB. Приём цен требует совпадения пары, формата, рынка и времени до старта карты. Для решающей карты BO3 цена серии допустима после подтверждённого закрытия рынка второй карты с нужным победителем. Пробелы печатаются с причиной. При ошибке API предыдущий архив сохраняется.

Коэффициент равен 1 / историческая цена токена. Это справочное значение с запрошенным шагом в одну минуту. Для оценки PRE требуется подтверждённая цена рынка карты до первого пика или бана. Для оценки POST берётся первая подтверждённая цена этого рынка после полного драфта до первого игрового действия. `started_at_utc` OpenDota может обозначать запуск игрового сервера до драфта, поэтому для границ фаз нужны отдельные доказательства. Снимки рынка серии и цены без подтверждённой фазы доступны как справочные данные.

В рабочем контуре активные драфты проверяются каждые две секунды. После подтверждения полного драфта сервер сразу запрашивает обе стороны точного рынка карты и повторяет запрос в пределах 10-секундного окна. Автоматический и ручной POST используют сохранённую котировку одной карты. Для измерения задержки хранятся время последнего пика при наличии независимой отметки, время получения драфта и время захвата цены.

Для зарегистрированных лиг LEON фоновый сбор заранее сопоставляет события с расписанием по обеим командам, формату и времени. POST обращается к уже привязанному событию и принимает открытые цены обеих сторон только для номера текущей live-карты. Идентификаторы из конфигурации служат резервом для заранее подтверждённых событий.

Для BLAST используется `--tournament blast-slam-ix`. Когда отдельного рынка третьей карты нет, а счёт 1:1 подтверждён только после её старта, снимок серии до окончания карты маркируется `series_at_1_1_late` и не попадает в статистику цен до старта. Опциональный `--events-json` позволяет повторить поиск на сохранённом ответе Gamma.
